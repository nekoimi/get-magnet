# B01 列表发现与分页落地记录

日期：2026-09-26。

## 交付

- 新增 `list_detail`（单个列表页到详情）与 `paginated_list`（分页列表到详情）模板，使用通用 `records` 写入链路。原单页及 JSON 模板保持可用。
- 工作流增加 `listing` 配置：`detail_selector`、可选 `next_selector`、`max_pages`（1–100）、`max_empty_pages`（1–10）。选择器使用 CSS，读取链接的 `href`。字段提取规则配置在原有 `nodes` 中，作用于详情页。
- 列表页从最终 URL 解析相对链接，去除片段并去重，只接受 HTTP(S) 同入口主机的链接。外站、空链接及脚本链接不会派生任务。获取结果重定向到其他主机时任务失败，不继续提取和派生；这不是浏览器子资源或网络访问隔离策略。
- `trigger` 是入口列表，`list` 是后续分页列表，`detail` 是详情；每个子任务保留 `parent_task_id`。同次运行、同角色、同 URL 只创建一个任务，附加页码不会改变去重身份。详情沿用通用记录写入、观察及原始文档来源关联。
- 无下一页、重复下一页、连续未发现新详情的列表页、达到最大列表页数时停止派生。停止原因保存在任务尝试结果的 `stop_reason` 中；达到页数上限且仍有下一页时带 `limited=true`。沿用运行聚合：有记录的截断运行显示 `limited`，完全没有有效记录仍为失败。其他预算及恢复增强属于 B02。
- 列表流程拒绝浏览器 `navigate` 动作覆盖任务 URL；其他动作可按 `list`/`detail` 过滤，根列表也按 `list` 过滤。浏览器逐动作真实联调仍按 A03 发版验收。

## 样例与界面

迁移 `2026_09_26_003` 为 `workflow_samples` 增加 `page_role`，旧样例默认 `trigger`。列表定义的样例应选择 `list` 或 `detail`。

- 列表预览展示去重后的详情链接及下一页，不访问这些链接，也不写正式任务或记录。发布前至少需要一份发现详情的列表样例，以及一份提取和保存预览通过的详情样例；所有已保存样例都必须通过。
- 实时详情样例需要填写同入口主机的 HTTP(S) URL，粘贴和历史文档仍可使用。预览和正式获取共用动作角色过滤。
- 采集器向导提供两个新模板和列表配置，创建时先保存列表样例；工作台可补详情样例并回归、发布。详情字段沿用数据集映射、CSS/属性编辑和高级 JSON。
- 运行页按父子关系展示任务树，区分入口列表、分页列表和详情，显示父任务 ID。仍受现有详情接口前 500 个任务的限制，大规模任务分页及检查面板在 B05 完善。
