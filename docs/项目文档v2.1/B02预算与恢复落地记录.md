# B02 预算与恢复落地记录

日期：2026-09-26。

## 预算契约

工作流定义可选 `budget`。缺省按入口主机设置：每页发现 100、总任务 1000、已预留页面 500、深度 100、运行 1800 秒、域名 1。`allowed_domains` 是精确主机名列表；填写额外主机时须同步提高 `max_domains`。发布校验要求所有数字为正且处于上限范围，入口主机必须在允许列表中。新运行把预算快照写入 `workflow_runs.budget`，不会因编辑工作流而改变；历史进行中的运行首次领取任务时从绑定的版本补齐快照。

- 每页发现统计同一列表页实际派生的详情任务；重复详情不重复占用。总任务与深度在插入子任务的运行锁内检查，避免并发父任务超额。页面额度按任务首次访问预留，任务重试复用预留额度。
- 域名额度按运行去重持久化，HTTP 重定向在发出下一次请求前检查允许域名与域名额度；浏览器服务执行后的最终 URL 也检查，但该检查不构成浏览器内部网络访问隔离。
- 运行时长以 `workflow_runs.created_at` 计算，使用运行上下文截止时间。后台恢复轮询同时关闭超时运行尚在排队、重试或执行的任务；正在写入的一批记录无法在数据库事务内部精确到毫秒中断。
- 预算截断写入 `run_limit_events`，原因包含 `max_discovered_per_page`、`max_tasks`、`max_pages`、`max_depth`、`max_duration_seconds`、`max_domains`、`allowed_domains`。`summary.coverage` 汇总任务数、已预留页面、已有文档页面、最大深度、访问域名和限制原因。运行详情接口和工作区显示覆盖范围与限制事件。已有有效记录且截断的运行是 `limited`；无有效记录仍是 `failed`，用户取消是 `cancelled`。

## 恢复与操作语义

迁移 `2026_09_26_004` 新增运行预算、任务深度/页面预留、域名与限制事件。过期租约恢复在运行锁和任务锁内更新任务及旧尝试；重新领取先关闭旧尝试，再创建新尝试。派生任务核对父任务当前租约和尝试号，同运行按页面角色及 URL 去重。

通用记录任务保存文档、截图和任务文档引用使用同一事务。重试时若已有文档，使用这份快照提取和派生，不重新访问可能已变化的页面；记录写入沿用 `workflow-task:<task_id>:item:<index>` 幂等键。取消运行会使执行中的写入失去运行锁许可；取消父任务时递归取消其未完成子任务。预算截断、用户取消不允许直接重试任务，应创建新运行；失败任务可在原运行预算期限内重试。重新运行继承原运行版本和预算，但获得新的时间窗口与计数。
