# B03 触发器落地记录

## 已实现

- `workflow_schedules` 保存每个工作流的五段 cron、IANA 时区、启停、并发策略、上次和下次触发时间。数据库迁移先于调度器启动；调度器轮询数据库，不依赖进程内注册，重启后继续处理到期时间及待派发事件。
- `workflow_schedule_events` 保存每次到期的 `pending/started/skipped/failed` 结果和运行 ID。事件插入、时间推进、运行创建在同一事务内完成，调度行锁和唯一键避免重复派发。服务离线错过多个周期时只补一次到期触发，再计算当前时间之后的下一次运行，不无限回放历史周期。
- `skip` 在该工作流已有 queued/running 运行时记录跳过；`queue` 保留 pending 事件，待已有运行结束后按事件顺序创建运行。停用工作流同时停用调度并标记待处理事件。
- `/api/v2/workflows/schedule` 与 `/api/v2/workflows/schedule/save` 提供认证后的配置和最近事件；`/api/v2/workflows/run/api` 通过现有登录认证创建运行并返回 `run_id`。API 目前只允许 `workflow_id` 和空 `input`，不接受 URL、页面状态或凭据覆盖。手动、定时、API 分别写入 `manual/cron/api`。
- 采集器工作台增加触发器配置、下次运行和事件记录；运行列表显示来源。未提供 webhook 配置。

## 约束

- 当前 API 触发复用登录认证，不提供独立机器令牌或细粒度项目授权。运行覆盖参数白名单为空；将来增加可覆盖参数与凭据引用时，需要先建立项目和凭据授权范围。
- 每个工作流目前只有一个定时配置。编辑配置会跳过旧配置的待处理事件。停止工作流会停用其定时配置，重新发布版本不会自动重新启用定时。
