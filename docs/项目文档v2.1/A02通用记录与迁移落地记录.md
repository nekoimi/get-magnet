# A02 通用记录与迁移落地记录

日期：2026-09-25。代码已实现，并在 `config/dev.yaml` 指向的开发 PostgreSQL 上完成迁移和写入验证；生产库迁移仍需按部署流程执行。

## 写入契约

- `records` 按 `(dataset_id, canonical_key)` 归并，`record_observations` 保存来源、原始候选、规范化字段及写入决策，`record_revisions` 保存新增/更新时的字段快照与变更字段。
- 写入事务先锁定数据集，按当前 Schema 校验字段类型、必填、唯一键；同数据集跨来源同键共用记录 ID。默认空值不覆盖已有非空值；多值字段合并去重。结果为 `created / updated / unchanged`，非法候选返回 422，重复幂等键但内容不同返回 422 冲突。
- 观察可引用 `workflow_version_id / run_id / task_id / document_id / source_id / source_url`。旧工作流写入磁力资源后追加任务证据观察；工作流任务的幂等键防止重试重复生成观察。
- 新接口：`POST /api/v2/records/create`、`GET /api/v2/records/list?dataset_id=…`、`GET /api/v2/records/detail?id=…`。创建接口不接受运行证据 ID，由受信任的 worker 写入。

## 迁移与兼容

1. 迁移 `2026_09_25_006` 新建记录、观察、修订、映射及迁移异常表；`2026_09_25_007` 从现有 `resources` 读取磁力资源，**不再读 `magnets`**，按默认磁力数据集的键跨来源归并。
2. A01 的磁力模板原先以 `number` 为必填键。历史资源有 URL 或 `legacy-id` 回退键，故迁移生成 Schema v2，使用 `canonical_key` 必填、`number` 可选，保留 v1 历史定义。
   若默认磁力数据集已被人工改到 v3 以上，迁移会明确报错，需先在快照上处理 Schema 与回填规则。
3. 旧资源的 `#duplicate:<id>` 迁移后缀去除，多个旧资源可映射同一记录；各自有观察、来源和 `legacy_resource_id → record_id / observation_id` 映射。链接取同键资源合集。空键写入 `record_migration_issues`，不伪造记录。
4. 旧 `resources`、`magnets`、下载状态和旧 API 保留。旧磁力采集与 `/api/v2/resources` 创建/更新后调用适配器；若第二步失败，原写入可能已提交，API 明确报错，使用 `POST /api/v2/records/legacy/reconcile` 按资源 ID 游标重放修复。重放同一资源版本不会重复生成观察；失败原因记入 `record_migration_issues`，修复成功后清除。
5. 记录默认内容哈希按 PostgreSQL JSONB 规范化文本计算；迁移与运行写入一致。迁移使用 `pgcrypto`，目标数据库账号须能安装该扩展。

## 上线核对

迁移前按[阶段 0 记录](阶段0基线与验收记录.md)备份并在旧版本快照演练。部署后执行以下只读核对；异常行应逐一解释。

```sql
SELECT count(*) FROM resources WHERE resource_type='magnet';
SELECT count(*) FROM legacy_resource_records;
SELECT count(*) FROM record_migration_issues;
SELECT count(*) FROM resources r WHERE r.resource_type='magnet'
 AND NOT EXISTS (SELECT 1 FROM legacy_resource_records m WHERE m.legacy_resource_id=r.id)
 AND NOT EXISTS (SELECT 1 FROM record_migration_issues i WHERE i.legacy_resource_id=r.id);
SELECT d.code,count(*) FROM records r JOIN datasets d ON d.id=r.dataset_id GROUP BY d.code;
SELECT record_id,count(DISTINCT source_id) AS sources,count(*) AS observations
 FROM record_observations GROUP BY record_id HAVING count(DISTINCT source_id)>1 LIMIT 20;
SELECT m.legacy_resource_id,m.record_id,o.source_id,o.source_url
 FROM legacy_resource_records m JOIN record_observations o ON o.id=m.observation_id
 ORDER BY m.legacy_resource_id LIMIT 20;
```
