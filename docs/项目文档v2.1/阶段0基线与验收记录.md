# v2.1 阶段 0 基线与验收记录

更新日期：2026-09-25。此记录对应实施计划 V21-00～V21-03。当前工作机无法连接 PostgreSQL，也没有可用的浏览器服务，因此本文件区分**代码核对及固定样例通过**与**真实数据、服务联调待验**。

## 1. 当前能力与发布决定

| 定义能力 | 当前执行路径 | 发布决定 |
| --- | --- | --- |
| `manual`，固定绝对 HTTP(S) 入口 URL | Go 创建根任务，worker 使用浏览器获取 | 允许；运行输入不能覆盖入口 URL |
| `extract`、`discover`、`transform`、`validate`、`script` | `internal/workflow/worker.go` 逐节点执行；发现任务是详情页 | 仅在字段、选择器、`run_on` 和最终磁力写入字段可校验时允许 |
| CSS、XPath、受限 JSONPath | `internal/workflow/extract.go` | 仅允许可解析的表达式；JSONPath 限简单属性和数字下标 |
| `acquire`、`navigate`、`pagination`、`persist`、`event`、`deduplicate` 等旧 DSL 节点 | 现有 worker 没有对应执行分支 | 拒绝新发布；旧定义仍可读，旧已发布定义在运行时明确失败 |
| `cron`、`api`、`webhook`、Profile、凭据、输入/输出 Schema、预算字段 | 未形成完整可验证的执行闭环 | 拒绝新发布；不把静默忽略当作降级 |
| 非 `magnet` 资源类型 | 当前 `persistResource` 最终调用磁力 `SaveCollected` | 拒绝新发布；通用数据集写入属于 A 阶段 |
| 旧 provider 磁力任务与下载插件 | 仍在原有任务与插件路径 | 保留历史行为，不按新工作流定义判定 |

严格门禁用于版本校验、发布、手动运行和 worker 运行时。历史草稿读取仍使用宽松解析。422 响应提供 `data.issues[].path` 和 `reason`。当前仅输出首个阻断项，完整问题列表是后续体验优化。

**已知边界：**浏览器获取仍是唯一工作流获取器；JSON 固定样例验证提取器，不代表 JSON HTTP 获取已实现。`limited` 状态已有聚合约定，但尚无预算执行器产生该状态。运行资源数是成功任务返回的 `resource_id` 数量，不等于去重后的新增记录数。脚本可修改字段，发布时只对静态提取和转换链证明写入字段；运行时无有效资源仍判失败。跨域发现、网络目标地址限制、记录写入与任务完成之间的事务幂等边界留给 A/B 阶段。

## 2. 数据库只读盘点

在目标环境备份后，用只读账号执行以下查询并把结果填入验收记录。不要在生产库执行修改语句。

```sql
-- 版本与触发类型、节点类型；旧 definition 可能缺字段，查询只统计。
SELECT status, definition->'trigger'->>'type' AS trigger_type, count(*)
FROM workflow_versions GROUP BY 1, 2 ORDER BY 1, 2;

SELECT v.status, n->>'type' AS node_type, count(*)
FROM workflow_versions v
CROSS JOIN LATERAL jsonb_array_elements(
  CASE WHEN jsonb_typeof(v.definition->'nodes') = 'array' THEN v.definition->'nodes' ELSE '[]'::jsonb END
) n GROUP BY 1, 2 ORDER BY 1, 2;

SELECT v.status, n->>'type' AS acquire_type, count(*)
FROM workflow_versions v
CROSS JOIN LATERAL jsonb_array_elements(
  CASE WHEN jsonb_typeof(v.definition->'acquire') = 'array' THEN v.definition->'acquire' ELSE '[]'::jsonb END
) n GROUP BY 1, 2 ORDER BY 1, 2;

SELECT w.id, w.code, w.resource_type, v.id AS version_id, v.definition->'trigger'->>'type' AS trigger_type,
       jsonb_path_query_array(v.definition, '$.nodes[*].type') AS node_types
FROM workflows w JOIN workflow_versions v ON v.id = w.published_version_id
ORDER BY w.id;

SELECT 'workflows' AS entity, count(*) FROM workflows
UNION ALL SELECT 'workflow_versions', count(*) FROM workflow_versions
UNION ALL SELECT 'workflow_runs', count(*) FROM workflow_runs
UNION ALL SELECT 'crawl_tasks', count(*) FROM crawl_tasks
UNION ALL SELECT 'task_attempts', count(*) FROM task_attempts
UNION ALL SELECT 'documents', count(*) FROM documents
UNION ALL SELECT 'resources', count(*) FROM resources
UNION ALL SELECT 'magnets', count(*) FROM magnets;

SELECT resource_type, status, count(*) FROM resources GROUP BY 1, 2 ORDER BY 1, 2;
SELECT source_id, resource_type, canonical_key, count(*) AS copies
FROM resources GROUP BY 1, 2, 3 HAVING count(*) > 1 ORDER BY copies DESC LIMIT 100;
SELECT source_id, resource_type, count(*) AS rows, count(DISTINCT canonical_key) AS keys
FROM resources GROUP BY 1, 2 ORDER BY 1, 2;
SELECT status, count(*) FROM workflow_runs GROUP BY status ORDER BY status;
SELECT task_type, step_name, status, count(*) FROM crawl_tasks GROUP BY 1, 2, 3 ORDER BY 1, 2, 3;

-- 历史页面角色和存储量。
SELECT document_type, count(*) AS documents, sum(content_size) AS bytes FROM documents GROUP BY 1;
SELECT asset_type, count(*) AS assets, sum(content_size) AS bytes FROM document_assets GROUP BY 1;
SELECT jsonb_typeof(definition) AS shape, count(*) FROM workflow_versions GROUP BY 1;
```

旧定义分类应逐个用校验接口检查已发布版本，记录 `workflow_id/version_id/阻断路径/处理决定`。拒绝项先停用或修订新草稿后发布；不可直接改写旧版本。原本未实现但曾被发布的配置可能在升级后停止运行，这是有意的显式失败，需要在上线前清点。

## 4. 备份、回退与上线核对

1. 停止新工作流发布与手动运行，记录当前镜像/commit、数据库迁移版本、活跃 `workflow_runs` 数量。
2. 用与实际连接配置一致的 PostgreSQL 凭据做整库备份，例如 `pg_dump -Fc -f scrapio-before-v21-stage0.dump "$DATABASE_URL"`，核对退出码、文件大小和 `pg_restore -l` 可读；在隔离库试恢复并核对上节行数。
3. 执行只读盘点，列出被新门禁拒绝的**已发布**版本；对每条安排新草稿或停用。先在隔离环境运行本地 CI 契约，再上线代码。
4. 上线后核对 422 阻断路径、有效磁力定义的手动运行、空结果失败、部分成功及重试，观察旧 provider 路径。浏览器离线应得到明确失败及重试记录。
5. 回退代码到记录的旧镜像/commit；阶段 0 没有数据结构迁移，不需要反向 DDL。若此期间产生了新运行，回退前停止 worker 并核对未完成租约；保留运行和文档历史。需要整库恢复时先在隔离库验证，再按实际数据保留要求决定切换，避免覆盖上线后的有效写入。
