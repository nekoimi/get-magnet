# scrapio v2.1 管理界面产品设计

> 状态：设计草案；依据 [scrapio v2.1 产品规划](采集平台v2.1产品规划.md) 制定。本文定义用户看到和操作的产品，不以 v2.0 的页面、接口或数据表作为设计边界。
>
> 使用环境：自用或小团队，单实例部署；桌面浏览器为主要操作环境。

> 命名：产品和主采集平台为 **scrapio**，独立浏览器执行服务为 **scrapio-browser**；管理界面属于 scrapio。

> 可点击演示：[管理界面 v2.1 交互原型](管理界面v2.1交互原型.html)。单文件 HTML，使用示例数据展示项目、数据、采集器和运行的主要路径。

## 1. 产品主张与重设计目标

管理界面要呈现一款**长期维护信息来源和数据资产的采集产品**。使用者关心的是“我想持续掌握哪些信息、现在有哪些数据、数据是否可靠、哪里需要我处理”；创建采集器只是达成这个目标的一步。

产品承诺：在一个采集项目里定义目标数据，接入一个或多个网页/API 来源，持续获得可查询、可追溯的记录；当来源变化、结果异常或运行中断时，平台指出影响范围并帮助恢复。用户可从目标与数据结果出发，也可进入规则和运行细节。

### 1.1 三个使用时刻

| 使用时刻 | 用户要完成的事 | 首页或项目页应给出的回答 |
| --- | --- | --- |
| 建立新项目 | 明确想收集的数据，从第一个来源拿到有效记录 | 目标数据集是什么、下一步该配置什么、首次采集是否成功 |
| 日常查看 | 了解新记录和变化，查询、筛选、导出或查看来源 | 最近有效更新时间、发生了什么变化、数据是否可信 |
| 异常处理 | 发现来源失效或字段质量下降，评估影响并修复 | 影响哪个项目和数据集、从何时开始、哪条规则失败、修复后是否恢复 |

### 1.2 现有界面的断点

当前 v2.0 界面的主要断点：

| 当前体验 | 给使用者造成的问题 | v2.1 的处理 |
| --- | --- | --- |
| 顶层分为采集源、工作流、运行记录、资源等实现对象 | 新建任务前要理解后台模型，采完后也没有面向目标的概览 | 用“项目”承接持续的信息需求；数据、采集器和运行分别承担结果、规则和排错 |
| 工作流以列表、弹窗、抽屉和 JSON 文本框为主 | 规则、样例、版本和运行之间频繁跳转，无法连续调试 | 使用独立的采集器工作台，保留草稿上下文和预览结果 |
| 测试偏向单组提取字段 | 测试通过也不能证明列表发现、详情获取、去重及保存决策正确 | 预览覆盖当前模板的完整链路，逐步展示输入和输出 |
| 运行页优先显示 Run、Task、Attempt ID | 需要凭内部 ID 猜测哪个页面或字段出了问题 | 先显示采集器、页面 URL、阶段、结果和错误；ID 放入技术详情 |
| 导航中混有历史磁力/下载能力及模板演示页 | 主产品路径不清晰 | 核心导航只围绕创建、数据、运行与系统维护；外部动作放在按需出现的集成入口 |

v2.1 的重点是**从目标、来源到可信数据的完整体验**。规则开发和排错是其中的关键能力；复杂画布、更多统计卡片或全站视觉换肤不构成产品目标。

### 1.3 产品对象及其关系

```text
一个实例（默认一个项目，可按需新增）
  └─ 采集项目：例如“影片资料库”——目标、成员、健康与最近变化
      ├─ 数据集：影片——字段定义、记录、质量、导出
      ├─ 采集器：站点 A 详情、站点 B 列表——来源规则、版本、调度
      └─ 运行：每次采集的过程和结果——页面、错误、记录变更
```

项目是轻量的**业务组织单位**，不承担租户隔离。初装自动提供默认项目，用户可直接输入 URL 开始采集；只有存在多个信息目标时才需要新建项目。一个数据集可以接收同项目多个采集器的结果。跨项目复用数据集是否必要留待真实使用验证，不作为首版前置能力。

### 1.4 产品体验的成功标准

第一次使用能从目标 URL 走到一条可查询且有来源的记录；第二次打开能直接看到数据是否更新、来源是否健康；出现异常时能从受影响的数据集进入失败页面并验证修复。三条路径都要在界面中走通，不能仅以“规则保存成功”作为验收。

## 2. 设计原则与范围

1. **从目标与结果开始。** 用户输入目标 URL 后即可开始试采；默认项目自动承接结果，站点、采集源、节点类型等概念按需展开。
2. **配置和反馈同屏。** 修改获取方式、发现规则或字段规则后，在同一工作台查看受影响的样例和结果。
3. **所见能力与执行能力一致。** 前端根据服务端能力和定义版本展示选项；未实现的步骤、触发器或浏览器动作不能被保存为可发布配置。
4. **预览与正式运行有清晰边界。** 预览默认不写正式数据、不触发插件；界面标明使用的是保存样例还是实时访问、测试范围和资源预算。
5. **错误指向可修复的位置。** 从运行错误能进入页面样例、字段规则或预算设置；错误不只出现在一次性消息中。
6. **日常使用优先于一次性配置。** 首页和项目页优先显示数据变化、健康与待办，规则编辑只在创建或维护时进入。
7. **小团队保持轻量协作。** 优先减少创建首个有效采集器所需的概念和操作；保留负责人、版本、编辑者和审计信息，支持协作追溯。

## 3. 信息架构

### 3.1 一级导航

```text
项目           目标、数据概览、来源健康、最近变化、待处理问题
数据           数据集、记录、筛选、变更、质量和导出
采集器         来源规则、草稿、样例、版本和调度
运行           运行历史、页面任务、失败定位和重试
设置           浏览器/HTTP 能力、凭据与会话、容量、操作记录
```

默认打开最近使用的项目概览；只有一个项目时不显示项目切换的额外负担。“采集源/站点”仅在确实需要共用域名设置、请求策略或凭据时作为采集器的组织属性，不要求预先创建。插件和外部动作在有可用集成时出现在“设置”和采集器的“外部动作”区域，不占用首版核心导航。磁力数据作为某个数据集及其字段模板呈现。

导航遵循 **项目看整体、数据看结果、采集器改规则、运行查过程**。同一对象可从多个入口到达，但页面标题、面包屑和返回路径保留原始项目上下文。

### 3.2 采集器详情的局部导航

```text
采集器名称 / 状态 / 已发布版本 / 最近运行
概览 | 配置与预览 | 样例 | 运行 | 版本 | 调度
```

“配置与预览”是编辑工作台；其余页签围绕同一个采集器保留上下文。列表和详情均支持按名称、站点、模板、状态及最近异常筛选。面包屑与返回链接必须保留筛选条件，避免排错后丢失工作位置。

### 3.3 页面之间的主要路径

| 起点 | 操作 | 到达位置 |
| --- | --- | --- |
| 项目概览的“最近新增” | 查看记录 | 数据集中的对应记录和来源 |
| 项目概览的“待处理” | 查看影响 | 受影响的数据集、采集器和失败运行 |
| 项目概览或采集器列表 | 添加来源 | 创建向导，项目和数据集已预选 |
| 采集器详情 | 编辑规则 | 配置与预览，打开当前草稿 |
| 字段预览错误 | 修改规则 | 同一步骤的该字段编辑控件 |
| 运行详情的页面错误 | 修正规则 | 基于失败输入创建草稿/样例，并定位步骤 |
| 数据集记录 | 查看来源 | 来源页面、运行和采集器版本 |
| 版本列表 | 对比/回滚 | 差异页；回滚生成新的待发布草稿 |

### 3.4 项目概览：日常工作的主屏

项目页回答“这份数据现在怎么样”，而不是堆通用统计：

```text
影片资料库                        最近有效更新：今天 09:20       [添加来源]
目标：持续收集影片基础信息与磁力资源；负责人：我

需要处理（2）
  JavDB 采集器：详情标题字段命中率从 98% 降到 42%  [查看影响与修复]
  备用来源：连续 3 次无新页面，最后成功 2 天前     [查看运行]

数据概况
  影片 12,480 条 · 今天新增 38 · 更新 6             [浏览记录]
  来源覆盖：JavDB 运行正常；备用来源需要处理

最近变化                        来源与调度                    活动
  新记录 / 字段变更              下次运行 / 最近成功            最近发布 / 修改者
```

指标必须可点击进入对应记录或运行；没有历史基线时显示“尚无基线”，不虚构异常。健康状态由最近运行、数据质量和更新时间共同决定；“运行成功但 0 条有效记录”需要结合预期判断，不一律显示健康。

### 3.5 项目中的三条任务路径

- **新增来源**：选择项目和目标数据集 → 输入 URL → 配规则 → 试运行 → 首次写入 → 返回项目页查看新增记录。新增来源默认建议复用现有数据集，减少同类数据散落。
- **使用数据**：项目页看到变化 → 数据集筛选记录 → 查看字段、来源和变更 → 导出当前筛选。数据页对不懂采集规则的成员也能独立使用。
- **恢复质量**：项目待办显示影响 → 运行页定位页面或字段 → 从失败输入建立样例 → 修改草稿并回归 → 发布 → 观察下一次运行与质量恢复。

## 4. 创建采集器：向导与工作台

### 4.1 创建向导

首次创建使用任务式向导，按实际依赖顺序进行。若从项目的数据集进入，自动带入项目与数据集；若从全局“添加来源”进入，使用最近项目或默认项目：

1. **想得到什么**：选择已有数据集或填写目标记录名称与几个期望字段；允许稍后完善 Schema，不让数据模型成为首次试采的障碍。
2. **从哪里获取**：填写 URL 或接口地址，命名采集器，选“单页详情 / 列表到详情 / 分页列表 / JSON 接口”模板。模板卡片说明输入、输出和适用场景。首轮只展示已经可运行的模板。
3. **获取样例**：默认尝试 HTTP；需要渲染时切换浏览器。显示最终 URL、状态、耗时、内容类型、正文预览和截图（如有）；获取失败时显示可执行的原因与建议。
4. **标注路径**：单页模板直接进入字段；列表模板先圈定详情链接；分页模板再定义下一页和停止条件；JSON 模板选择数组路径。每次选择显示匹配数量与示例 URL。
5. **定义输出**：补全数据集字段、类型、是否必填、多值规则和唯一键。用样例实时显示原始值、转换值、缺失与冲突。
6. **试运行和发布**：在有界范围内跑完整流程，查看页面、候选记录和预计保存决策；保存代表性样例，通过发布检查后发布。

向导允许保存草稿并稍后继续。未完成步骤显示缺失项，不以虚假的“完成”状态提示用户。每个步骤提供少量解释和一个主要动作，技术选项折叠在“高级设置”。新建时不要求用户填写 JSON。首次正式运行后的结束页展示一条实际记录、它的来源，以及“查看全部数据”和“返回项目”两个明确去向。

### 4.2 配置与预览工作台

向导创建的规则与后续修改使用同一工作台：

```text
采集器 / 示例商品采集                  草稿 v4 · 未发布      [保存草稿] [试运行] [发布]
┌─────────────────┬─────────────────────────────────┬──────────────────────────┐
│ 步骤与状态       │ 当前步骤的规则                    │ 样例与预览                │
│ 目标与模板   ✓   │ 规则字段、匹配方式、参数和说明      │ 页面 / JSON / 截图切换     │
│ 获取方式     ✓   │                                 │ 匹配高亮、候选 URL        │
│ 发现与分页   !   │ 仅展示当前模板需要的设置           │ 字段值、校验、预计入库动作 │
│ 输出字段     ✓   │                                 │ 错误位置与建议            │
│ 数据集与去重 ✓   │                                 │                          │
│ 测试与发布   ·   │                                 │                          │
│ 调度         ·   │                                 │                          │
└─────────────────┴─────────────────────────────────┴──────────────────────────┘
```

步骤状态分为“未配置、待验证、通过、有问题”；状态来自保存的定义与最近一次对应样例测试，修改规则后相关步骤回到“待验证”。预览面板固定显示样例来源、获取时间、规则版本和是否为实时访问。窄屏下步骤区收起，预览移到配置下方；不要求在手机上完成复杂规则编辑。

### 4.3 高级编辑

高级 JSON 编辑和表单编辑读写**同一份带版本号的采集器定义**。切换前校验、展示差异并保留未保存内容；JSON 中有表单无法表达的已支持配置时，表单标出只读区域，禁止无提示地丢字段。校验错误定位到 JSON 路径，并对应到可见步骤。多人同时编辑时提示草稿版本冲突，提供比较和显式覆盖选择。

## 5. 样例、调试与发布

### 5.1 样例工作区

样例分为列表页、详情页、JSON 响应及异常输入；每份样例记录来源 URL、页面角色、获取方式、获取时间、内容类型、正文/截图引用、备注和预期结果。支持“实时获取并保存”“从历史运行保存”“上传或粘贴样例”（只在解析器可接受的格式内）。保存样例时隐去凭据和敏感请求头。

样例列表显示最近通过的规则版本与失败字段。使用者可标记正常详情、字段缺失、空列表等预期状态；“空列表”不自动被当成采集失败。样例原文默认作为不执行脚本的只读内容预览。

### 5.2 预览、试运行与回归

| 操作 | 目的 | 输入与副作用 | 必须展示的结果 |
| --- | --- | --- | --- |
| 当前步骤预览 | 快速调试选择器、浏览器动作或字段 | 一个保存样例或一次实时获取；不入库 | 原始输入、命中位置、原始值、转换值、错误 |
| 完整试运行 | 验证模板全链路和边界 | 明确入口、最大页面/任务数、超时；默认不入库、不触发插件 | 访问页、发现 URL、候选记录、校验、唯一键、预计新增/更新/未变/冲突 |
| 样例回归 | 防止规则修改破坏已知页面 | 保存样例集，不重新访问网站 | 每份样例和每个字段的新旧结果差异 |

完整试运行若因预算停止，显示“受限结束”与已覆盖范围；不把部分结果写成完整成功。实时获取的资源消耗和目标站点访问范围在启动前可见。提取失败、获取失败、唯一键缺失、重复记录分别展示。

### 5.3 发布检查

发布页是一张可核对清单：目标与域名、使用的获取方式、模板步骤、数据集 Schema 和唯一键、样例回归、运行预算、触发器、潜在外部动作、相对已发布版本的差异。阻断项和提醒项分列。阻断项至少包括：定义版本不兼容、所选能力不可执行、必需步骤缺失、唯一键无法生成、相关样例回归失败、预算缺少必填上限。

发布生成不可变版本；已启动运行继续引用原版本。发布成功页提供“手动运行”和“查看运行”入口。发布前的试运行结果与发布后的正式写入结果必须用不同状态和文案区分。

## 6. 数据集与记录

数据集页先展示“这类记录包含什么、由哪些采集器产生、最近质量如何”，然后再提供字段配置。页面顶部展示最近有效更新、新增与变化、异常字段、来源覆盖；中间是可查询的记录，Schema 和写入策略放在设置页签。创建数据集时定义名称、记录类型、显示字段、字段类型、必填规则、唯一键和更新策略。磁力模板只是可选的预填字段，不是所有数据集的固定列。

记录列表依据数据集 Schema 生成列与筛选项；固定提供状态、来源、首次发现和最近发现时间。默认显示数据集选定的“主标题 + 关键字段”，避免一打开就是动态 JSON 列。记录详情显示规范化值及原始值、字段变更、唯一键、来源页面、运行、采集器版本。发现字段缺失时可跳到对应运行页面或采集器的字段规则。导出明确数据集、筛选范围、字段和文件大小；大结果集采用后台任务并显示进度。用户保存常用筛选视图后，可从项目页直接打开该视图；首版视图仅保存筛选和列设置，不引入复杂报表功能。

## 7. 运行中心与故障定位

### 7.1 运行列表

默认先看“需要处理”：失败、部分成功、受限结束、质量异常；可切换全部运行。每行优先展示采集器、触发方式、开始时间、耗时、访问页数、候选记录、新增/更新/未变/无效、最终状态。运行 ID 可复制，但不占主列。筛选条件可由 URL 保存和分享。

### 7.2 运行详情


## 8. 首次使用、团队协作与系统设置

首次使用提供一个默认项目。空项目页以“你希望持续收集什么”为起点，给出“从网页开始”“从 JSON 接口开始”“查看示例”三个入口。示例展示真实的目标、来源和结果关系，不预置会访问未知站点的运行任务。完成第一次正式采集后，项目页立即替换为数据与健康概览；不再重复显示新手向导。

小团队协作以“谁负责、谁改了什么、是否可回退”为主：项目显示负责人，采集器显示最近修改者和已发布版本，发布操作写明变更摘要；草稿冲突要提示并可比较。首版不建设复杂的角色矩阵或审批流。数据使用者可以只通过项目和数据页完成查询，不需要接触规则编辑。

系统设置集中展示 scrapio 的 HTTP 获取能力与 scrapio-browser 是否可用、浏览器支持的动作与限制、凭据/会话引用、运行容量、存储占用与样例保留策略、操作记录。连接故障给出受影响的项目和采集器，以及测试/运行入口。用户不能在采集器表单中选择当前实例没有的执行能力。

## 9. 界面状态与交互规范

| 状态 | 表现与操作 |
| --- | --- |
| 空状态 | 说明该区域会出现什么，提供与当前任务直接相关的创建或返回动作 |
| 加载中 | 保留页面骨架与当前筛选；长时间获取显示阶段和取消方式 |
| 请求失败 | 在内容区保留错误、重试入口和请求范围；Toast 只作即时补充 |
| 无匹配结果 | 显示当前筛选并提供清除筛选；不等同于系统无数据 |
| 草稿未保存 | 离页提醒，并明确保存/放弃；自动保存若启用需显示同步状态 |
| 能力不可用 | 控件禁用并说明依赖或最低版本；不可发布的配置给出精确路径 |
| 部分成功 | 同时展示成功产物和失败页面；保留原因和下一步操作 |

操作按钮以任务语言命名：“获取样例”“预览字段”“完整试运行”“发布版本”，避免用“执行”“提交”等含糊动词。状态颜色配合文字与图标，不只靠颜色区分。字段结果和错误支持键盘定位及复制；URL、JSON、原文有溢出与大文本处理。原始 HTML 默认转义或沙箱隔离，不执行目标站点脚本。

## 10. 与现有界面的衔接

| 现有入口 | v2.1 去向 | 迁移原则 |
| --- | --- | --- |
| 仪表盘 | 默认项目概览 | 将运行数字转成数据变化、来源健康和待处理问题；保留可点击的历史统计 |
| 工作流 | 采集器列表与详情 | 现有工作流作为迁移来源，只有能映射到受支持模板的定义才允许在新工作台发布 |
| 采集源 | 采集器的站点组织与默认设置 | 保留必要的共享配置，不再作为创建前置步骤 |
| 运行记录与任务队列 | 运行中心 | 历史 ID 保留可查，页面优先呈现业务上下文和错误 |
| 资源中心/磁力资源 | 数据集与记录 | 旧磁力数据迁移到通用数据集；保留来源与兼容字段 |
| 快速采集 | 采集器中的手动运行 | 运行前显示版本、输入范围与写入行为 |
| 插件监控 | 按需的集成管理 | 插件失败与采集失败分开追踪 |

迁移期间为旧链接提供重定向或只读历史页。历史运行若没有页面/字段级信息，应明确标为“旧版运行，缺少该信息”，不伪造完整追溯。生产导航移除模板演示页和不属于核心采集流程的下载入口。

## 11. 分阶段交付与验收

| 阶段 | 前端交付 | 从界面验收 |
| --- | --- | --- |
| A：看得到的首次价值 | 默认项目、目标与来源向导、单页/JSON 工作台、通用数据集、样例预览、发布检查、首次记录页 | 不写 JSON 也能分别创建非磁力和磁力采集器；正式运行后从项目页进入可查询记录并查看来源；不支持的配置不能发布 |
| B：持续采集与日常使用 | 项目健康概览、列表/分页步骤、完整试运行、页面任务树、预算与调度、部分成功状态、数据变化与常用筛选 | 第二次打开产品能判断数据是否更新及来源是否健康；异常能从项目页追到失败详情页和字段 |
| C：可恢复的质量 | 样例集、回归差异、历史文档回放、字段质量趋势、版本比较与回滚、负责人及变更摘要 | 页面结构变化后，不重新访问站点也能定位、修复、回归并发布新版本；项目健康状态随成功运行恢复 |
| D：可选扩展 | 脚本编辑与测试、AI 建议审核、显式插件订阅及历史 | 扩展能力只在服务端真实支持时出现，输入、结果、费用或副作用可追踪 |

每阶段采用至少三个不同站点、两类数据集的真实任务验收。记录首次正确入库耗时、首次记录查询耗时、第二次打开时判断健康所需时间、配置时的迷路或返回次数、失败定位耗时、发布被错误阻断/放行次数及“运行成功但无有效结果”的次数。交付标准是用户在界面中完成任务，页面存在或接口返回成功不单独算通过。

## 12. 仍需通过试用确定的选择

1. 首轮三个站点及其样例页面、两类数据集，以及各数据集的实际使用方式，用来确定向导、记录列表和常用筛选的优先级。
2. 默认 HTTP 获取失败时，是否建议一键转为浏览器获取；决定前需验证 scrapio-browser 的实际能力和资源消耗。
3. 样例、原始文档和截图在单实例下的默认保留期与容量提示阈值。
4. 多人编辑同一草稿的常见程度；首版至少提供版本冲突保护，再依据使用情况决定是否增加协同编辑。
5. 一个项目包含多个数据集和采集器是否足够覆盖实际组织方式；先不引入跨项目共享和细粒度权限。

这些选择不影响先建立“项目目标 → 来源配置 → 可信数据 → 健康与修复”的主路径。

## 13. 原型视觉方向

[可点击 HTML 原型](管理界面v2.1交互原型.html)参考了 `采集平台设计/index.html` 的控制台布局：深靛蓝侧栏、白底选中导航、紧凑的指标卡、运行趋势与动态列表、任务树旁的检查面板。整体采用中性蓝灰底色和蓝色交互强调；绿色仅表示运行正常或校验通过，橙色与红色分别提示关注和失败。窄屏使用可收起的侧栏，表格允许横向滚动，详情检查面板转为纵向排列。

参考稿展示的是 v2.0 业务对象；v2.1 原型沿用本文的“项目 / 数据 / 采集器 / 运行 / 设置”导航。运行趋势和动态服务于项目健康判断，页面检查面板展示字段、执行尝试及输入输出，不让旧的工作流、资源中心和任务队列概念重新成为一级入口。
