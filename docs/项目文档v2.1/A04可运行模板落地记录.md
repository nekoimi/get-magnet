# A04 可运行模板落地记录

日期：2026-09-26。两个模板的获取、提取、转换、校验和通用记录写入已接通，并在开发 PostgreSQL 完成正式任务执行验收。模板向导及原型风格的管理工作台留在 A06；完整 dry-run、样例与版本锁定留在 A05。A03 的真实浏览器动作联调仍待完成。

## 模板与调用契约

`GET /api/v2/workflows/templates` 返回两份可编辑的定义：

| 模板标识 | 获取与提取 | 默认输出数据集 |
| --- | --- | --- |
| `single_page` | HTTP HTML 页面，CSS 提取绝对 canonical URL、标题和正文 | `article` 类型，`url` 为唯一键 |
| `json_api` | HTTP JSON 接口，从 `$.items` 数组逐对象提取 `$.url`、`$.title`、`$.body` | 同一文章数据集 |

模板中的 `example.org` URL 是占位示例，需替换目标 URL、字段规则和数组路径后运行。通过现有 `/workflows/create` 创建采集器时指定项目、文章数据集及 `resource_type=article`，`definition` 仍按现有 API 契约传 JSON 字符串；接着调用版本校验、发布和手动运行接口。发布会核对数据集必填字段、唯一键与输出字段名；缺少唯一键或存在未知输出字段的定义会被阻断。

新定义显式使用 `persistence=records`，直接写 `records/record_observations/record_revisions`。未指定该字段的历史磁力定义继续使用旧磁力适配器。新通用记录路径目前支持一个 `extract` 节点及后续 `transform/validate`，列表发现、分页和脚本尚未开放在这条路径；平台会拒绝这类配置，不静默忽略。两个模板均无需浏览器；可将获取模式改为 A03 已支持的 `browser`，真实浏览器仍需完成联调。

## JSON 路径范围

- 支持根 `$`、对象字段 `$.data.items`、非负数组索引 `$.items[0].url`，可组合嵌套。字段名范围为字母/下划线开头，后续可包含数字与连字符。
- `extract.config.items_path` 用于选中对象数组，须配合 `content_type=json` 和 `persistence=records`。选中数组后，字段路径相对于每个数组对象的 `$`，不再相对于原始响应根。
- 不支持通配符、递归下降、过滤、切片和引号字段路径；发布与执行都明确拒绝。缺失路径、非数组、非对象数组成员和空数组会失败。当前每批支持 1–1000 个对象，超限拒绝整批，不能默默截断。

## 保存与运行证据

候选先共用提取、转换和校验代码，再按数据集 Schema 校验。所有候选通过后，`SaveBatch` 在一个数据库事务中执行归并与证据写入，任意候选失败回滚整批。每项幂等键为 `workflow-task:<task_id>:item:<index>`，观察保存采集器、发布版本、运行、任务、原文和来源引用。成功结果返回逐项 `created/updated/unchanged`，运行摘要统计记录写入次数及各决策次数；这不是全平台去重后的记录总数。没有正式记录的运行不能算成功。

保存前核对提取时读取的 Schema 版本，若 Schema 在提取与写入之间变化则拒绝写入。发布版本锁定 Schema 和样例的完整契约在 A05 继续完善。非法候选当前会让页面任务失败，保留原始文档用于排查；不会产生部分成功的批次或额外插件事件。

真实任务测试发现任务保护锁与观察外键写入会互相等待，故 `WithActiveAttempt` 使用 `FOR NO KEY UPDATE`：允许另一个事务取得外键引用需要的 KEY SHARE 锁，同时继续阻止取消、重新领取和任务状态更新越过当前写入。

## 验收证据

- 固定契约测试覆盖两个模板、JSON 对象数组、字段转换、可选字段、空必填多值字段、缺少数据集唯一键和不支持的 JSONPath。
- 开发库测试使用本机 HTTP 服务提供 HTML/JSON 页面，正式执行 worker 并持久化原文与记录。单页创建记录；JSON 运行更新同键记录并新增第二条；再次 JSON 运行得到两项 `unchanged`。最终为 2 条记录、5 条观察、3 条修订；所有运行状态为 `succeeded`。非法批次验证没有残留部分记录。
