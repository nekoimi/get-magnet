# A05 样例与预览落地记录

日期：2026-09-26。A05 面向 `persistence=records` 的新采集器版本。旧磁力版本继续使用原有发布路径；列表发现与分页属于 B 阶段，当前 dry-run 覆盖 A04 单页和 JSON 数组模板的完整获取、提取、转换、校验、Schema 校验与保存决策。

## API 与使用顺序

1. 创建工作流和草稿版本，取得 `version_id`。
2. `POST /api/v2/workflows/samples/create`：传 `version_id`、`source`、`note`。`source=paste` 另传 `content_type=html|json` 与 `content`；`source=document` 另传属于此工作流运行的 `document_id`；`source=live` 按版本定义实时获取。三种来源均保存原文快照、内容哈希、页面 URL 和版本引用。实时获取仅在创建样例时访问网络，以后的回归不访问网络。响应只返回样例元数据。
3. `GET /api/v2/workflows/samples/list?version_id=...` 查看版本样例元数据；`POST /api/v2/workflows/samples/delete` 传 `id`，只允许删除草稿样例。
4. `POST /api/v2/workflows/samples/preview` 传 `version_id` 与 `sample_id`；也可传 `content_type`、`content`、`page_url` 即时预览而不保存。可选 `idempotency_keys` 数组逐项检测已有观察的键冲突。返回 `dry_run=true`、`fetched_live=false`、每个执行步骤的值快照、候选的预计决策及失败原因。`POST /api/v2/workflows/versions/check-samples` 传 `id`，回归该版本全部样例。
5. `POST /api/v2/workflows/versions/publish` 传 `id`。新通用记录草稿必须至少保存一个样例，且所有样例通过。发布事务锁住版本与数据集；保存或删除样例和发布不能交叉。发布后样例保留在该版本，创建新草稿须为新版本重新准备样例。历史已退休版本的回滚保留兼容路径。

样例原文限制为 10 MiB；API 请求体有 11 MiB 上限。历史文档必须属于同一采集器，保存的内容和类型与原文一致。样例引用的历史文档即使随后清理，快照仍可用于回归。

## 预览语义

`TraceRecordCandidates` 与正式 worker 的 `RecordCandidates` 共用同一执行路径。步骤依次显示载入样例、提取、转换、校验；各节点后保留值快照。保存预测读取现有记录，按候选顺序在内存模拟批内同键归并，返回 `created/updated/unchanged`。非法候选显示 `invalid` 及失败节点；提供幂等键且与已有观察不一致时显示 `conflict`。无幂等键的普通预览不会凭空产生冲突。正式任务的幂等键来自任务 ID，因此预览结果只是一份当前数据库状态下的预测，其他任务并发写入或 Schema 更新可改变正式结果。完整正式保存仍以 `SaveBatch` 事务为准。

预览不调用 `SaveBatch`，不创建任务、运行、正式记录、观察、修订或插件事件。实时保存样例只执行获取并保存样例快照，不写正式记录。失败的批次不能通过发布门禁。

## 验证与限制

- `go test -timeout 120s ./...` 通过；模板 trace 与正式候选一致的固定测试通过。
- 显式开发库测试验证：无样例阻断发布；HTML、JSON 与同工作流历史文档样例可预览；篡改历史文档内容会被拒绝；JSON 同键两项预测为 `created/updated`；预览前后正式记录、观察、修订与插件任务数相等；删除草稿样例后再次阻断发布；发布后的样例不可删除。测试在检查数据库名 `get_magnet_dev` 后执行，数据按测试 ID 清理。复验命令：`$env:SCRAPIO_TEST_DEV_A04='1'; go test -timeout 120s ./internal/repo/workflow_repo -run TestDevRecordTemplatePublication -count=1; Remove-Item Env:SCRAPIO_TEST_DEV_A04`。
- 浏览器实时样例使用 A03 的统一获取协议；真实 CloakBrowser 环境的逐动作联调尚未完成。A06 将把这些接口接入原型风格的采集器工作台。
