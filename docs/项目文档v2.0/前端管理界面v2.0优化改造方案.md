# 前端管理界面 v2.0 优化改造方案

## 1. 文档目的

本文档定义 `ui/get-magnet-ui` 面向采集平台 v2.0 的管理界面改造方案。

当前前端仍然以“磁力链接下载管理”为中心：

- 一级菜单包含“磁力链接”“下载管理”“播放与 STRM”。
- 磁力资源详情同时展示采集、云盘、下载和播放后处理状态。
- 采集管理只有采集状态和 JavDB 快速提交。
- API、TypeScript 类型和页面字段大量依赖 `magnets`、`download_*`、`cloudTask`。
- 路由中仍保留大量 vue-next-admin 示例页面，业务导航和模板演示混在一起。

v2.0 前端需要围绕新的通用采集模型组织：

```text
仪表盘
  ├── 采集源
  ├── 工作流
  ├── 运行任务
  ├── 资源
  ├── 原始文档
  └── 系统运维
```

前端不再把云盘、aria2、STRM 和下载后处理作为核心工作区。后续这些能力通过插件页面或独立插件前端接入。

## 2. 改造目标

### 2.1 业务目标

- 使用者可以从采集源、工作流、运行记录和资源结果四个层面管理平台。
- 工作流支持草稿、测试、发布、停用、版本对比和回滚。
- 一次运行可以查看完整的任务树、重试记录、原始页面和提取结果。
- 资源详情展示通用字段，并兼容现有磁力资源数据。
- 页面能够区分“采集成功”“资源重复”“规则无效”和“执行失败”。
- 不配置下载服务时，核心前端功能完整可用。

### 2.2 技术目标

- API 客户端从 `/magnets`、`/download` 逐步迁移到 `/resources`、`/workflows`、`/runs`、`/tasks`。
- TypeScript 类型与 v2.0 数据库实体保持一致。
- 消除下载字段在通用资源页面中的隐式依赖。
- 将页面状态拆分为列表状态、详情状态、运行状态和编辑器状态。
- 为长任务提供轮询、取消、重试和失败详情。
- 保持 Element Plus 和现有布局体系，减少一次性更换 UI 框架的风险。

## 3. 当前前端现状

### 3.1 现有业务路由

当前主要业务路由位于 `src/router/route.ts`：

```text
/home                 仪表盘
/magnets              磁力链接
/download/queue       下载队列
/download/aria2       Aria2 控制台
/crawler/status       采集状态
/crawler/quickSubmit  快速提交
/settings/runtime     系统设置
/media                播放与 STRM
/ops/health           健康与版本
/ops/jobs             调度任务
```

此外还存在大量模板演示页面，例如 `pages/*`、`fun/*`、`make/*` 和 `visualizing/*`。这些页面不应继续出现在生产业务导航中。

### 3.2 当前耦合点

- `src/views/magnets/index.vue` 同时显示资源、下载错误、云盘任务和 STRM 信息。
- `src/views/download/queue/index.vue` 依赖 `download_retry_count`、`download_error`、`cloudTask` 等字段。
- `src/views/home/index.vue` 的摘要包含“待提交、下载中、已完成、失败”。
- `src/views/settings/index.vue` 包含 cloud-driver、aria2 和 STRM 配置测试。
- `src/api/magnet`、`src/api/download`、`src/api/cloudDriver` 使用旧领域命名。
- `src/types/views.d.ts` 中的资源类型仍包含下载和播放字段。
- `src/api/crawler` 使用 `submitJavDB`、`submitJavDBPage` 等站点专用接口。

## 4. v2.0 信息架构

### 4.1 一级导航

建议生产环境一级导航调整为：

```text
仪表盘
采集平台
  ├── 采集源
  ├── 工作流
  ├── 运行记录
  ├── 任务队列
  └── 快速采集
资源中心
  ├── 全部资源
  ├── 磁力资源
  └── 原始文档
系统运维
  ├── 服务健康
  ├── 调度任务
  ├── 配置管理
  └── 操作审计
系统管理
  ├── 用户
  ├── 角色
  └── 菜单
```

第一阶段可以不做“全部资源”和“磁力资源”两套页面，先用资源类型筛选统一资源列表。

### 4.2 旧路由调整

| 旧路由 | v2.0 处理 | 说明 |
| --- | --- | --- |
| `/magnets` | 改为 `/resources` | 统一资源列表，保留磁力字段兼容展示 |
| `/download/queue` | 下线 | 下载能力移出核心平台 |
| `/download/aria2` | 下线或插件外链 | 不出现在核心导航 |
| `/media` | 下线或插件外链 | STRM 不属于核心资源管理 |
| `/crawler/status` | 改为 `/collection/runs` | 从实时 worker 状态升级为运行历史 |
| `/crawler/quickSubmit` | 改为 `/collection/quick` | 选择工作流后提交 URL |
| `/settings/runtime` | 拆为 `/system/config` 和 `/system/health` | 运行配置与依赖健康分开 |
| `/ops/health` | 保留并改造 | 增加数据库、浏览器服务、任务队列状态 |
| `/ops/jobs` | 改为 `/collection/tasks` 或保留别名 | 展示持久化任务和调度器状态 |

旧路由可以在迁移期保留重定向，但不再保留旧页面中的下载操作。

## 5. 页面设计

### 5.1 仪表盘

仪表盘从“下载统计”改成“采集运行概览”。

核心指标：

- 资源总数。
- 今日新增资源。
- 今日运行次数。
- 执行中的运行。
- 待处理任务。
- 失败任务。
- 最近一次成功运行。
- 浏览器服务状态。

主要区域：

1. 资源状态分布。
2. 最近运行列表。
3. 失败任务列表。
4. 来源产出趋势。
5. 系统依赖状态。

移除：

- 待提交下载。
- 下载中。
- 下载完成。
- STRM 数量。

点击统计卡片应跳转到带过滤条件的资源、运行或任务页面，而不是只展示数字。

### 5.2 采集源

路由建议：`/collection/sources`。

列表字段：

- 名称。
- 稳定 code。
- 类型。
- 启用状态。
- 关联工作流数量。
- 最近运行时间。
- 最近运行结果。

详情页分为：

- 基本信息。
- 默认入口。
- 浏览器 profile。
- 关联工作流。
- 最近运行。
- 配置变更历史。

操作：

- 新建。
- 编辑草稿。
- 启用/禁用。
- 测试连接。
- 运行关联工作流。

### 5.3 工作流

路由建议：`/collection/workflows`。

列表字段：

- 工作流名称。
- 来源。
- 资源类型。
- 当前发布版本。
- 状态。
- 调度表达式。
- 最近运行。
- 最近结果。
- 更新时间。

详情页建议采用三栏布局：

```text
左侧：步骤导航/节点树
中间：当前步骤配置
右侧：输入样例、输出预览、校验结果
```

第一版不要求实现复杂的自由画布。推荐先实现有顺序的步骤编辑器：

```text
入口 -> 浏览器操作 -> 列表发现 -> 分页 -> 字段提取 -> 转换 -> 校验 -> 入库
```

现有 `src/views/pages/workflow` 的 jsPlumb 工作流示例可以作为交互参考，但不应直接作为生产工作流数据模型。

工作流操作：

- 新建草稿。
- 从已有版本复制。
- 校验配置。
- 使用样例页面测试。
- 查看变更 diff。
- 发布版本。
- 回滚版本。
- 手动运行。
- 导出/导入 JSON。

发布前必须展示：

- 配置错误。
- 缺少必填字段。
- 未引用的步骤。
- 可能产生大量任务的分页风险。
- 浏览器 profile 和凭据引用风险。

### 5.4 运行记录

路由建议：`/collection/runs`。

列表字段：

- Run ID。
- 工作流。
- 工作流版本。
- 触发来源。
- 状态。
- 任务总数。
- 成功/跳过/失败数量。
- 新增资源数。
- 开始时间。
- 耗时。

筛选条件：

- 工作流。
- 来源。
- 状态。
- 触发类型。
- 创建时间范围。
- 是否有失败任务。

运行详情采用任务树：

```text
运行摘要
├── 根任务
│   ├── 列表页
│   ├── 详情页 A
│   ├── 详情页 B
│   └── 下一页
└── 运行事件时间线
```

详情区域包括：

- 运行摘要。
- 任务树。
- 失败任务。
- 重试记录。
- 产出资源。
- 原始文档。
- 规则版本。
- 运行日志。

操作：

- 取消运行。
- 重试失败任务。
- 按原版本重新运行。
- 复制输入创建新运行。

### 5.5 任务队列

路由建议：`/collection/tasks`。

与运行记录不同，任务队列关注当前待处理和异常任务：

- queued。
- running。
- retry_wait。
- failed。
- dead_letter。
- interrupted。

列表字段：

- Task ID。
- Run ID。
- 步骤。
- URL 或输入摘要。
- 当前状态。
- 尝试次数。
- 下次重试时间。
- 租约状态。
- 最近错误。
- 更新时间。

操作：

- 立即重试。
- 取消任务。
- 查看完整输入。
- 查看执行尝试。
- 查看浏览器请求和响应摘要。

### 5.6 快速采集

路由建议：`/collection/quick`。

当前页面只支持 JavDB 详情页/列表页，v2.0 改为：

- 选择工作流。
- 输入一个或多个 URL。
- 选择是否允许分页。
- 选择最大派生任务数。
- 选择是否保存原始页面。
- 提交并返回 Run ID。

提交成功后不只显示“任务已提交”，应直接提供：

- Run ID。
- 查看运行详情。
- 当前排队数量。
- 预计执行状态。

### 5.7 资源中心

路由建议：`/resources`。

列表不再命名为“磁力链接”，而是通用资源列表。

通用字段：

- 标题。
- 资源类型。
- 来源。
- 唯一键。
- 资源状态。
- 来源 URL。
- 首次发现时间。
- 最近更新时间。

筛选条件：

- 资源类型。
- 来源。
- 状态。
- 标题/唯一键关键词。
- 创建时间。
- 是否存在链接。

磁力资源额外显示：

- 磁力链接数量。
- 优选链接。
- 链接名称和优先级。
- 站点特有属性。

详情页采用标签页：

1. 基本信息。
2. 属性数据。
3. 资源链接。
4. 来源页面。
5. 采集历史。
6. 原始文档。
7. 事件时间线。

移除或隐藏：

- 下载任务 ID。
- 下载进度。
- 云盘保存路径。
- STRM 路径。
- 播放文件。
- 下载重试次数。

如果未来安装了 delivery 插件，可在单独的“插件任务”标签中展示，不混入资源核心字段。

### 5.8 原始文档

路由建议：`/resources/documents`。

用途：

- 查看某次任务获取到的 HTML、JSON、截图和元信息。
- 查看 content hash、大小和抓取时间。
- 使用指定工作流版本重放提取。
- 对比不同版本的提取结果。

页面布局建议：

```text
左侧：文档列表
中间：HTML/JSON/文本预览
右侧：提取结果和版本信息
```

原始文档页面必须默认转义 HTML，禁止直接执行文档内脚本。

### 5.9 系统运维

保留当前运维页面，但调整检查对象：

- PostgreSQL。
- 浏览器执行服务。
- 控制平面自身。
- 任务调度器。
- 任务队列积压。
- 最近错误率。

删除核心设置页面中的：

- aria2 配置。
- cloud-driver 配置。
- STRM 配置。
- 下载调度配置。

部署连接地址、日志级别等属于运行配置；工作流和采集源属于业务配置，两者必须在 UI 中分开。

### 6.3 TypeScript 类型


资源类型示意：

```ts
export interface Resource {
  id: number;
  resource_type: string;
  source: ResourceSource;
  source_url: string;

```

磁力特有字段应放在类型扩展中，不要把下载状态继续加入通用 `Resource`。

## 7. 组件和状态管理

### 7.1 建议新增的通用组件

```text
components/domain/StatusTag.vue
components/domain/ResourceTypeTag.vue
components/domain/RunSummary.vue
components/domain/TaskTree.vue
components/domain/ExecutionTimeline.vue
components/domain/JsonViewer.vue
components/domain/DocumentPreview.vue
components/domain/WorkflowVersionBadge.vue
components/domain/EmptyState.vue
```

### 7.2 Pinia 状态边界

不要将所有业务状态放入一个全局 store。建议按页面工作区拆分：

- `useCollectionStore`：来源、工作流和运行筛选。
- `useRunStore`：运行详情、任务树和轮询状态。
- `useResourceStore`：资源列表、详情和筛选条件。
- `useWorkflowEditorStore`：草稿、当前步骤、校验结果和未保存变更。
- `useSystemStore`：健康状态和运行配置摘要。

列表分页、筛选条件和详情缓存由页面 store 管理；登录用户、主题和权限继续由现有 store 管理。

### 7.3 长任务轮询

v2.0 初期使用轮询，不急于引入 WebSocket：

- 运行详情页每 2~5 秒刷新一次。
- 运行进入终态后停止轮询。
- 页面离开时取消请求。
- 失败时显示最后一次更新时间和重试按钮。
- 后端未来支持 SSE/WebSocket 时，前端保留统一的 `RunProgressSource` 抽象。

## 8. 交互和视觉规范

### 8.1 信息密度

这是运营型管理工具，不使用营销式大卡片和大面积装饰。页面优先保证：

- 表格可扫描。
- 状态可比较。
- 操作位置稳定。
- 详情可追溯。
- 错误信息可定位。

### 8.2 状态表现

统一状态标签颜色和文案：

| 状态 | 颜色建议 | 说明 |
| --- | --- | --- |
| `queued` | info | 等待执行 |
| `running` | warning | 执行中 |
| `retry_wait` | warning | 等待重试 |
| `succeeded` | success | 成功 |
| `skipped` | info | 正常跳过 |
| `failed` | danger | 执行失败 |
| `dead_letter` | danger | 超过重试次数 |
| `cancelled` | info | 已取消 |

“重复资源”不显示为错误，应使用独立的正常状态或事件类型。

### 8.3 错误交互

错误列表至少提供：

- 简短错误摘要。
- 完整错误详情。
- 发生步骤。
- 第几次尝试。
- 最后更新时间。
- 查看输入/原始文档。
- 重试操作。

不要只使用 `ElMessage` 显示一次性错误，长任务错误必须持久化在详情页面。

### 8.4 响应式布局

- 运行详情的任务树在窄屏下切换为抽屉或上下布局。
- 工作流编辑器在移动端优先使用步骤列表，不强行显示画布。
- 表格列提供可配置显示和横向滚动。
- JSON、HTML、日志内容必须限制最大高度并支持复制。

## 9. 权限设计

建议将权限从页面级扩展到操作级：

```text
source:read / source:write
workflow:read / workflow:write / workflow:publish
run:read / run:create / run:cancel / run:retry
task:read / task:retry / task:cancel
resource:read / resource:write / resource:delete
document:read / document:replay
system:read / system:write
```

高风险操作需要二次确认：

- 发布工作流。
- 回滚工作流。
- 批量重试任务。
- 删除资源。
- 删除原始文档。
- 修改浏览器 profile 或凭据引用。

## 10. 页面迁移顺序

### 第一阶段：核心导航清理

- 移除下载管理、Aria2、播放与 STRM 一级菜单。
- 将磁力链接页面改名为资源中心。
- 将采集状态改为运行记录入口。
- 保留快速提交，但改成工作流选择。
- 仪表盘移除下载统计。

### 第二阶段：资源和运行页面

## 13. 设计原则

1. 前端领域命名与后端 v2.0 数据模型保持一致。
2. 资源页面展示采集资源，不承载下载生命周期。
3. 运行页面展示过程，资源页面展示结果，两者通过 ID 关联。
4. 配置编辑必须有草稿、校验和发布，不直接修改运行中版本。
5. 长任务错误必须可追溯，不依赖一次性 toast。
6. 复杂工作流优先使用可理解的步骤编辑器，画布编辑器后置。
7. 原始页面只读、可重放、默认安全隔离。
8. 下载和其他外部动作通过插件页面扩展，不污染核心菜单和通用类型。
